JOURNEY STRIP
Homepage → Registration → Personal Journal
FLOW_CONNECTION ← From: Homepage, Login
→ To: S-JRN-01 (Personal Journal on success)

On success: Auto-login, redirect to Personal Journal
On error: Display inline validation errors
Special cases: Duplicate email/username checked on submit
UX_NOTE "Progressive Disclosure principle applied - Only essential fields visible (email, username, password). No optional fields to distract users during signup. Clean, centered layout emphasizes the primary action."
DEV_NOTE API: POST /api/auth/register
Validation:
- Email: valid format, unique
- Username: 3-30 chars, alphanumeric + underscore, unique
- Password: min 8 characters
- Confirm: must match password
On success: Auto-login via session cookie, redirect to /journal

Field Hierarchy

PRIMARY Email, Username, Password
SECONDARY Confirm Password (validation only)

JOURNEY STRIP
Login → Forgot Password → Login (via email link)
FLOW_CONNECTION ← From: S-AUTH-02 (Login page)
→ To: S-AUTH-02 (Login page on success)

On success: Show generic success message (prevents account enumeration)
MVP Note: Admin-assisted password reset if email infrastructure not ready
UX_NOTE "Error Prevention principle - Generic success message shown whether email exists or not, preventing account enumeration attacks. Clear guidance about what to expect next."
DEV_NOTE API: POST /api/auth/forgot-password
Behavior:
- Always show success message (security)
- Send email if account exists
- Rate limit: 3 requests per hour per IP
MVP Fallback: Admin-assisted reset via support

JOURNEY STRIP
Navigation Menu → Account Settings → Same Page (refresh)
FLOW_CONNECTION ← From: Navigation menu (user dropdown)
→ To: Same page (refresh on update) or Homepage (on delete)

On email update: Send confirmation email, show success toast
On password update: Show success toast
On delete: Show confirmation modal, then redirect to Homepage
UX_NOTE "Error Prevention First principle - Current password required for any security changes. Clear visual separation between safe actions (update) and dangerous actions (delete) using red danger zone styling."
DEV_NOTE APIs:
- PUT /api/user/email (requires current password)
- PUT /api/user/password (requires current + new password)
- DELETE /api/user/account (cascade delete all user data)

Validation:
- New email: valid format, unique
- New password: min 8 chars, matches confirm
- Current password: must be valid

Field Hierarchy

PRIMARY Current Password, New Password
SECONDARY Current Email, New Email
TERTIARY Delete Account (destructive)
